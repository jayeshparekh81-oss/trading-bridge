RECOMMENDATION
  Use S1 (NSE official) ALONE for the full universe — values AND announcement
  dates from the same filing rows:
    * quarters ending Jun-2020 -> Dec-2024: /api/corporates-financial-results list
      + one detail call per chosen filing (consolidated preferred, standalone
      fallback) -> EPS basic+diluted + broadCastDate/filingDate + reInd flag;
    * quarters ending Mar-2025 -> now: /api/integrated-filing-results + one XBRL
      fetch per consolidated filing -> Basic/Diluted EPS + broadcast_Date +
      revised_Date.
  S2 (thecore) is NOT a data source (no dates, shallow depth, restated) but is a
  free sanity-check: its recent-quarter EPS matched S1 6/6 exactly in the
  cross-check — worth one pass as an independent value check on recent quarters.
  S3 (BSE) is rejected: 2-quarter depth, standalone-only figures, no dates, and
  no coverage of NSE-only names (BSE Ltd, CDSL).

  Estimated full-universe cost (~190 names): per symbol ~2 list calls +
  ~19 old-regime detail calls (Jun-2020..Dec-2024) + ~6 XBRL fetches (2025->) ->
  ~27 requests/symbol, ~5,100-5,500 total incl. warm-ups/retries. At the 1 req/s
  budget: ~90-100 minutes single-threaded, one evening run, fully cache-resumable.

HONEST RISK PARAGRAPH — the single biggest risk in the recommended source

  The recommendation rests entirely on NSE's UNDOCUMENTED private APIs: cookie-
  warm-up sessions, 401-recycling, and endpoints NSE can throttle, reshape, or
  wall off at any time — a ~5,000-request evening crawl is exactly the access
  pattern their bot defenses exist to stop, so the full fetch may need multiple
  resumed sessions and could stall entirely. Beyond availability, the probe
  already caught silent COVERAGE HOLES in the very source of truth: TMPV's
  migrated history is missing the 30-Jun-2020 quarter outright, and pre-2016 rows
  return empty detail payloads — so the full fetch must end with a per-symbol ×
  per-quarter completeness audit (expected 19+6 quarters each, every gap named),
  not a row count. Field variance (bank vs non-bank EPS keys, multi-context XBRL
  values, occasional '0' diluted entries) is real but mechanical; the hole risk
  and the access risk are the ones that can quietly corrupt a backtest.
