# B3.2 — Gate the 3 clean premium endpoints (spec, no code)

**Goal:** attach `require_active_plan` (B3.0) to the three premium *surfaces* that are clean separate endpoints. Behavior-neutral until `PAYWALL_ENFORCED` is flipped ON. Risk: **Medium**.

## Exact endpoints to gate (swap `get_current_active_user` → `require_active_plan`)
All currently depend on `get_current_active_user`; the swap keeps auth (require_active_plan composes on it) and adds the plan check.

1. **Analytics**
   - `GET /api/users/me/trades/stats` — `backend/app/api/users.py` (~line 676)
2. **Complete trade history**
   - `GET /api/strategies/executions` — `backend/app/strategy_engine/api/strategies.py`
   - `GET /api/users/me/trades` — `backend/app/api/users.py` (~line 585)
   - `GET /api/users/me/trades/export` — `backend/app/api/users.py` (~line 632)
3. **Transparency Ledger**
   - `GET /api/marketplace/listings/{id}/ledger` — `backend/app/strategy_engine/api/marketplace.py`
   - `GET /api/marketplace/listings/{id}/ledger/history`
   - `POST /api/marketplace/listings/{id}/ledger/verify` *(see Risks — confirm verify is premium)*

## Response / field changes
- **No response-shape change.** On entitlement failure (flag ON + non-active) the endpoint returns the B3.0 paywall response: `402 {code:"PLAN_REQUIRED", message, upgrade_url:"/pricing"}`. On success, identical body to today.
- Both `users.py` (default `= Depends(...)`) and the strategy_engine routers (`Annotated[..., Depends(...)]`) just change the dependency callable — no signature reshaping.

## MUST NOT touch (stay FREE / never gated)
- `GET /api/strategies`, `GET /api/strategies/{id}` (strategy cards/detail)
- `GET /api/marketplace/listings` (marketplace browse)
- `POST /api/strategies/{id}/backtest` (basic backtest — handled separately in B3.3)
- `get_current_active_user`, auth, onboarding, system, pricing, and ALL sacred/execution paths.

## Tests (mandatory)
Per gated endpoint (sqlite + dependency-override pattern, like `tests/test_admin_set_plan.py`):
1. **Lockout-guard (critical):** a `plan_status='none'` user still gets **200** on every FREE endpoint (strategies list/detail, marketplace browse, basic backtest) — under flag **ON and OFF**. This is the regression that guards against accidentally gating a free surface.
2. **Flag OFF ⇒ everyone passes:** none/active/expired all get 200 on the gated endpoints (current behavior preserved).
3. **Flag ON + active (non-expired) ⇒ 200.**
4. **Flag ON + none/expired/cancelled ⇒ 402 `PLAN_REQUIRED`** on each gated endpoint.
5. **Auth still first:** no token ⇒ 401 (not 402) on a gated endpoint.
6. Use B3.0's `_set_flag`-style monkeypatch of `paywall_enforced` for ON/OFF.

## Risks
- **Shared-endpoint risk (primary):** `GET /api/users/me/trades` / `/trades/stats` may be consumed by a non-analytics (free) page too. **Before swapping, grep the frontend for every caller** of these paths; if a free surface depends on one, that endpoint can't be gated as-is (split or reconsider). The lockout-guard test only covers known free endpoints — a hidden consumer won't be caught by it.
- **`ledger/verify` (POST):** confirm it belongs to the premium ledger surface vs. should stay free (it's a cheap chain-integrity check). Default: gate it; flip if product wants verify free.
- **Never gate the auth dep or a free endpoint** — a misplaced swap locks out all current (100% `none`) users on that surface (402 storm). Mitigated by default-OFF flag + lockout-guard test.
- No migration. No sacred/trading touch. Deploy batched with the rest of B3 (flag stays OFF).
