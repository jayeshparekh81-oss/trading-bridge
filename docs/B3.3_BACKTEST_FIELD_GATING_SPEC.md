# B3.3 — Backtest advanced-field gating (spec, no code) — **HIGH RISK, ISOLATE**

**Goal:** on `POST /api/strategies/{id}/backtest`, keep the **basic** backtest result FREE while gating the **advanced** analytics sections behind an active plan — by **nulling** the advanced fields when not entitled, NOT by 402-ing the endpoint (a 402 would kill free basic backtest). Risk: **High** — the only endpoint where a wrong split breaks a FREE feature.

## File / endpoint
- `backend/app/strategy_engine/api/backtest.py` — `POST /api/strategies/{id}/backtest`, response model `BacktestResponse` (~lines 211–218). **⚠️ strategy-engine-adjacent — see QUESTIONS before building.**

## Field split (BASIC stays, PREMIUM nulled when not entitled)
`BacktestResponse` fields, all already `Optional`/`| None` except the core result + `health_card`:
- **BASIC (always returned):** the core backtest result (`backtest`: pnl, win rate, trade count, trades/equity as currently shaped).
- **PREMIUM (→ `None` when not entitled):** `reliability`, `health_card`, `truth`, `regime`, `deviation`, `trade_quality`, `diagnosis`.
- **OPEN (confirm with product):** is the **equity curve** basic or premium? (frontend renders `EquityCurveChart` under "advanced metrics" but it may be part of the core result). Default: keep equity in BASIC unless product says otherwise.
- Note: `health_card` is non-Optional in the current model (`StrategyHealthCard`). Gating it to `None` requires making it `Optional` in the response model — confirm that's acceptable (additive, frontend already treats panels as possibly-absent).

## Mechanism
- **Do NOT** attach `require_active_plan` as a hard dep (keep `get_current_active_user`; basic stays free → 200, never 402).
- Add a **non-raising** entitlement check to `app/auth/entitlements.py` (B3.0 currently has the private `_has_active_plan`): expose `plan_is_active(user) -> bool` (= `_has_active_plan`) and a `paywall_active()` helper, so callers can branch without raising.
- After computing the response, if `paywall_enforced() and not plan_is_active(user)` → set the PREMIUM fields to `None` before returning. Flag OFF ⇒ unchanged (all sections present).
- **Optimization (optional, flag in PR):** skip *computing* the premium sections for non-entitled users (saves the reliability/walk-forward/regime/AI-doctor compute). Default to compute-then-null for safety/simplicity; the skip is a follow-up perf win if backtest latency matters.

## Tests (mandatory)
1. **Backtest-basic-stays-intact (critical):** flag ON + `plan_status='none'` ⇒ **200**, core `backtest` result present and correct, PREMIUM fields all `None`.
2. **Entitled ⇒ full:** flag ON + active ⇒ all sections present (same as today).
3. **Flag OFF ⇒ full for everyone** (current behavior preserved, incl. `none` users).
4. **No 402 ever from this endpoint** (basic backtest is free) — assert status 200 in all the above.
5. Reuse the existing backtest test harness; assert on the response JSON section presence/absence.
